# 수집 데이터

매일 GitHub Actions(collect)가 공고를 수집해 이 브랜치에 커밋한다. 코드는 main 브랜치에 있다.

| 경로 | 내용 | 바뀌는 방식 |
| --- | --- | --- |
| `state.jsonl` | 공고별 현재 상태: 처음 본 날, 마지막 본 날, 내려간 날, 마감일, 중복 대표, 잡음 여부 | 매일 다시 쓴다 |
| `postings/YYYY/MM/DD.jsonl.gz` | 그날 처음 본 공고의 원본(수집처 응답 포함) | 한 번 쓰면 고치지 않는다 |
| `details/YYYY/MM/DD.jsonl.gz` | 그날 받은 공고 상세(본문) | 한 번 쓰면 고치지 않는다 |
| `companies.json` | 회사별 기업 구분(수집처가 붙인 대기업·공공기관·외국계) | 매일 갱신 |
| `facts.jsonl` | 공고 정리: 후보 공고마다 AI가 뽑은 매칭 항목(핵심 업무, 스킬, 연수 요건 등) | 매일 추가 |
| `dart/corps.json` | 회사 기본정보: 공고 회사 키 → DART 고유번호 잇기 결과(못 찾았으면 이유) | 매일 갱신(못 찾은 회사는 30일마다 다시) |
| `dart/basics.json` | 회사 기본정보: DART 고유번호 → 기업개황, 사업보고서 주요 계정 3년, 직원 현황, 최근 1년 주요 공시 | 받은 지 30일이 지나면 다시 |
| `dart/listed.json` | 주요 기업 후보: DART에서 종목코드가 있는 회사 `[고유번호, 이름, 종목코드]`(상장 폐지 포함) | 7일마다 |
| `dart/filers.json` | 주요 기업 후보: 사업보고서를 낸 비상장 회사 `[고유번호, 이름, ""]`(그해 3~5월 제출분) | 7일마다 |
| `notes/<회사 키>.json` | 내 리서치 노트(정해진 블록, 형식은 main 브랜치 docs/content-rules.md "내 리서치 노트"). 매일 수집 때 사람마다 Supabase에 들어간다 | 노트를 만들거나 고칠 때 |
| `runs/YYYY-MM-DD.json` | 실행 요약(수집처별 건수, 새 공고, 내려간 공고, 오류) | 매일 추가 |

지난 공고는 소급해서 모을 수 없어서, 추이 분석은 이 브랜치가 쌓인 날부터 가능하다.
