# 내용과 화면 원칙

화면, 리서치, 매칭, 보고에 무엇을 어떤 형식으로 담나. 용어와 표기는 [용어집](glossary.md)을 따른다.

## 내용 원칙

1. 회사 리서치는 사실만 담는다. 해석과 제안(매칭 설명, 커리어 제안)에는 "AI 의견"을 붙이고 근거 링크를 단다.
2. AI가 쓴 문장마다 출처 URL이 있어야 하고, 없으면 버린다. 저장 전에 출처를 다시 열어 내용을 대조한다.
3. 숫자(실적, 임직원, 공시)는 공식 데이터를 그대로 쓴다. AI가 숫자를 만들지 않는다.
4. 사실 표시: 확인·보도는 배지 없음, 의견·미확인만 배지. 출처끼리 값이 다르면 둘 다 보여주고 미확인. 찾아봤지만 없으면 "찾지 못함".
5. AI 결과에는 설정 버전, 모델, 지시문 버전을 함께 저장한다.
6. 설정을 바꾸면 비용이 안 드는 필터는 전체에 바로 적용하고, AI 비용이 드는 것은 앞으로만 적용한다(원하면 골라서 재처리).

## 콘텐츠 형식 원칙

그릇은 고정하고 내용은 열어둔다. 형식을 너무 조이면 정보를 놓치고, 너무 풀면 화면과 문장이 매번 달라진다.

| 층 | 무엇 | 강도 |
| --- | --- | --- |
| 그릇 | 화면 블록 모양 | 항상 고정 |
| 칸 | 담을 항목 | 영역마다 다름(아래 표) |
| 문장 | 실제 글 | 길이와 규칙만 고정 |

- **블록 7개**: 숫자 카드·그래프, 라벨-값 줄, 비교 표, 사실 목록(날짜 + 한 줄 + 출처 + 배지), 단계 흐름, 인용, 칩. 화면의 모든 정보는 이 중 하나로 그린다.
- **AI 결과는 블록 형식의 JSON으로만** 받는다. 코드가 검증(필수 칸, 출처, 길이, 날짜 형식)하고, 실패하면 화면에 내보내지 않고 다시 생성하거나 버린다.
- **필수 칸과 찾아볼 주제를 나눈다.** 필수 칸은 데이터가 늘 있는 곳에만 둔다. 나머지는 주제로만 알려주고 못 찾으면 "찾지 못함". 주제 밖이어도 중요한 사실은 "기타"로 1~2개 허용한다.
- **고정 기준은 버전으로 관리한다**: 직무 분류, 스킬 사전, 매칭 점수 계산법, 수요 계산법. 바꾸면 버전을 올리고 지난 데이터를 다시 계산한다.
- **기준 샘플**: 공고 5개와 회사 5곳을 고정해 두고, 지시문이나 형식을 바꿀 때마다 다시 돌려 전후를 비교한다.
- **칸 올리기·내리기**: 자유 형식에 같은 정보가 자주 나오면 고정 칸으로 올리고, 고정 칸이 자주 비면 찾아볼 주제로 내린다.

| 영역 | 강도 | 고정 | 열어둠 |
| --- | --- | --- | --- |
| 공고 데이터 | 고정 | 필드, 값 형식, 직무 분류 | 원문 JD 보관 |
| 매칭 점수 | 고정 | 평가 항목, 가중치, 계산법 | - |
| 매칭 설명 | 반고정 | 맞는 점/부족한 점/지원 전략 구조, 개수·길이 상한, 근거 링크 | 문장 |
| 리서치 공시 숫자 | 고정 | 지표, 3년, 단위 | - |
| 리서치 서술 모듈 | 반고정 | 사실 목록 블록, 찾아볼 주제, 개수 상한 | 담을 사실, 기타 1~2개 |
| 커리어 지표 | 고정 | 직무 분류, 스킬 사전, 수요 계산법(아래 "커리어 지표") | - |
| 커리어 해석·제안 | 반고정 | AI 의견 표시, 근거, 카드 구조 | 문장 |
| 아침 알림·오늘의 리포트 | 고정 | 항목 순서·개수, 문구 틀 | 항목 안 짧은 요약 |
| 프로필 | 반고정 | 경력·프로젝트·스킬 칸, 스킬은 사전 기준 | 프로젝트 설명 |
| 내 모듈 | 반고정 | 모듈 정의 형식, 결과는 사실 목록 | 조사 주제 |
| 화면 문구·표기 | 고정 | 용어집 | - |
| 디자인 | 고정 | 색·글자 규칙, 컴포넌트 | 화면별 배치 |

## 커리어 지표

공고에서 센 사실만 쓴다. 계산법은 고정하고 버전으로 관리한다(`src/jobpost/career.py`의 VERSION, 화면 쪽 계산은 `web/src/lib/career.ts`). 지금 v2(2026-10-22, 리뷰 반영: 신입·이하 구간, 같은 공고 묶음의 날짜).

- **대상**: 국내, 같은 공고는 하나로(묶음은 가장 먼저 본 날부터, 하나라도 열려 있으면 열린 것으로), 잡음 제외. 직무 유형 × 기업 구분으로 나눠 두고 화면이 내 필터(직무 유형, 기업 구분)에 맞게 더한다. 커리어 방향이 아닌 유형(라벨링, 데이터·AI 아닌 직무, `config/job_types.yaml` direction: false)은 뺀다.
- **열린 공고(수요)**: 날마다 처음 본 날 ≤ 그날 < 내려간 날인 공고 수. 지난 공고는 소급할 수 없어 수집을 시작한 날(2026-10-13)부터다.
- **새 공고**: 그날 처음 본 공고 수. 수집 첫날은 그동안 열려 있던 공고가 한꺼번에 들어와 세지 않는다. 새로 붙인 수집처가 첫날 가져온 공고(원래 열려 있던 공고, `backfill`)도 같은 이유로 새 공고로 세지 않고 열린 공고에만 센다(커리어 지표 v3, 2026-10-29). 같은 날 다른 수집처에서 처음 본 공고와 묶이면 새 공고다. 기간 비교는 바로 앞 같은 길이 기간이 온전히 있을 때만 하고, 60일이 넘는 기간은 7일씩 묶어 그린다(맨 앞의 7일이 안 되는 묶음은 빼서 짧은 주가 줄어든 것처럼 보이지 않게).
- **경력 요구**: 지금 열린 공고의 최소 경력 구간(3년 미만, 3~7, 7~12, 12년 이상, 연차 무관). 신입이거나 "N년 이하"만 적힌 공고는 3년 미만, 경력이 아예 없으면 연차 무관. 내 연차는 프로필의 데이터·AI 경력.
- **요구 스킬**: 지금 열린 공고 본문에서 스킬 사전(`config/skills.yaml`)으로 찾은 스킬별 공고 수. 비율의 분모는 본문이 있는 공고 수. 내 스킬 중 사전에 없는 것은 "사전에 없음"으로 따로 표시한다(공고에서 셀 수 없어 0건이 아니다).
- **스킬 적합도**: 그 직무 공고가 많이 요구하는 스킬 20개 중 내가 가진 비율, 요구한 공고 수로 가중. 숙련도 2(실무) 이상은 1, 1(기초)과 안 고른 것은 0.5.
- **직무 지도**(2026-10-28까지 포지션 맵): 가로 스킬 적합도, 세로 열린 공고(내 기업 구분), 원 크기도 열린 공고 수, 진하기는 스킬 적합도, 어두운 빨강 테두리는 희망 직무. 칸 이름은 주력 · 도전 · 틈새. 범례는 한 줄(열린 공고 수 · 스킬 적합도 · 희망 직무), 차트 안 이름은 직무 유형의 짧은 이름. 가로 기준선은 50%, 세로 기준선은 보이는 직무(스킬 적합도가 있는 것)들의 가운데 값. 적합도를 셀 수 없는 직무(요구 스킬이 없는 직무)는 구역을 정하지 않는다. 위 오른쪽 주력, 위 왼쪽 도전, 아래 오른쪽 틈새, 아래 왼쪽은 이름 없음(지도 아래 묶음에서는 주력만 펼친다).
- **직무별 내 경력**: 프로필 직무 구간의 기간을 직무 유형으로 더한다(같은 id, 또는 `config/profile.yaml`의 job_type).
- **다른 방향**: 희망 직무가 아닌 직무를 (열린 공고 ÷ 가장 많은 직무의 열린 공고) × 스킬 적합도 순으로.
- **연봉**은 넣지 않는다. 공고에 거의 적혀 있지 않다(2026-10-21 공고 정리 340건 중 금액이 적힌 것 5건 남짓).
- 해석·제안(어느 방향이 좋은지 문장으로)은 아직 없다. 넣을 때는 "AI 의견"을 붙이고 근거 숫자를 함께 둔다.

## 아침 알림·오늘의 리포트

항목 순서와 문구 틀은 고정한다(알림은 `src/jobpost/notify.py`, 화면은 `web/src/copy.ts`). 알림 형식의 버전과 값(마감 임박 날 수·점수 기준, 이유 표시)은 `config/notify.yaml`에만 둔다.

**아침 알림**: 하루 두 통, 세 묶음. 묶음은 모두 접어 제목과 건수만 보이고 눌러서 펼친다. 첫 통은 1·3과 버튼, 둘째 통은 2(필터 밖이 있을 때만). 한 통이 길면 텔레그램 앱이 "더보기"로 잘라서 필터 밖을 떼었다.

1. 필터 통과 새 공고: 전부, 점수 높은 순.
2. 필터 밖 새 공고: 참고용(잡음 제외). 걸린 조건이 적은(아깝게 빠진) 공고부터, 회사 링크 없이. 필터가 안정될 때까지 공고마다 걸린 이유("필터 밖: 직무 기획·PM · 기업 구분 그 외", others_reason). 제외 키워드·회사에 걸리면 그것만, 아니면 걸린 조건 전부를 적는다.
3. 마감 임박: soon_days 안에 마감. 관심 공고 먼저, 그다음 필터 통과 공고 중 soon_min_score 이상.

- 새 공고는 지난 알림 다음 날부터 오늘까지 처음 본 공고(최대 1주일). 여러 날치면 머리에 기간("10/25~10/28(수)"). 지원했거나 관심 없음으로 둔 공고는 뺀다.
- 머리 건수는 두 통에 실제로 든 공고 수다(새 공고 = 필터 통과 + 필터 밖).
- 공고마다 판정 표시 · 회사 · 점수 · 마감, 제목. 회사는 회사 화면, 제목은 공고 상세로 잇는다. 아래 버튼은 리포트 · 공고 목록 · 커리어.
- 메시지 한도를 넘는 날은 필터 밖 → 마감 임박 → 필터 통과 순으로 뒤에서 줄이고 "외 N건"으로 알린다(필터 밖은 공고 목록에 없어 "줄였어요").
- 첫 통이 갔으면 보낸 것으로 기록한다(둘째 통이 실패해도 다시 돌릴 때 첫 통이 또 가지 않게).
- 사람마다 바꾸는 건 받기 켜기·끄기뿐(관리 > 아침 알림, Supabase `settings.notify.enabled`). 그 화면에 알림에 들어가는 것을 적는다.

**오늘의 리포트**: 이번 주(오늘 포함 최근 7일) 기준 네 덩어리. 머리(이번 주 공고 · 오늘 · 마감 임박 건수, 섹션에서 빼기 전 전부) → 오늘의 1등(최근 7일 필터 통과 새 공고 중 점수 1등, [회사 보기] [자세히 보기]) → 이번 주 새 공고(나머지, 점수 높은 순 10건 + 더 보기, 오늘 올라온 건 "오늘" 표시) → 마감 임박(관심 공고 먼저, 5건 + 더 보기) → 관심 회사 새 공고(★ 회사의 이번 주 새 공고, 필터와 상관없이, 5건 + 더 보기) → "열린 공고 전체 추천순 보기"(공고 탭). 위에서 보인 공고(펼친 것까지)는 아래에서 빼고, 지원했거나 관심 없음은 뺀다. "오늘"은 브라우저 날짜 기준. 열린 공고 전체에서 뽑는 1등은 몇 주씩 그대로라 두지 않는다.

**관리**: 메뉴(프로필·이력서, 아침 알림, 수집 현황)를 누르면 각 화면으로 넘어간다.

- 수집 현황: 오늘 공고를 믿어도 되는지만. 마지막 수집 시각, 수집처마다 정상 · 일부만 받음(일부만 받았으면 그 수집처 새 공고가 빠졌을 수 있고 내려간 공고 처리는 다음 수집으로 미룸), 내려감 기준 한 줄. 건수는 보여주지 않는다.
- 열림 · 내려감: 공고 상태는 둘뿐이다. 수집처 목록에 있으면 열린 공고, 사라지면 내려간 공고(일부만 받은 날은 내리지 않음). 지우지 않고 `data` 브랜치에 쌓는다. 공고 목록·리포트·알림에는 열린 공고만, 내려간 공고는 회사 화면 지난 공고에 "내려감 10.24"로 남는다.

## 회사 리서치 모듈

기본정보(공고가 들어온 모든 회사, 공시·수집 데이터, 비용 거의 없음)와 심층분석(관심 회사·직접 요청, AI 웹 조사)으로 나눈다.

| 모듈 | 구분 | 형식 | 갱신 |
| --- | --- | --- | --- |
| 회사 개요 | 기본 | 정해진 칸(3년 실적 그래프, 주요 사업, 임직원·근속·연봉, 주요 공시). v1은 주요 사업 없이(아래) | 새 공시가 나오면. v1은 30일마다 |
| 채용 | 기본 | 정해진 칸(열린 공고, 지난 1년 같은 직무 공고) | 매일 |
| 사업 구조 | 심층 | 자유(분야 + 한 줄, 주력·신사업) | 새 공시가 나오면 |
| 경쟁사 | 심층 | 표(같은 업종 매출 상위 2곳 자동) | 분기마다 |
| 직무 분야 전략 | 심층 | 사실 목록 | 관련 뉴스가 나오면 |
| 직무 조직 | 심층 | 사실 목록 + 찾지 못함 | 조직 개편 소식이 나오면 |
| 직무 환경·도구 | 심층 | 정해진 칸(클라우드, 데이터 플랫폼, BI, AI 도구) | 분기마다. v1은 매일(공고에서 센다) |

### 기본정보 v1(2026-10-21)

3. 굵기는 700(제목), 600(항목), 400(나머지)만
4. 설명 문장은 화면에 쓰지 않고 ? 아이콘이나 첫 사용 안내로
5. 목록 한 항목은 최대 4줄, 넘치면 말줄임. 공고 제목은 목록 제목(용어집) 한 줄이고 원문 제목은 공고 상세에
6. 출처·근거는 기본으로 숨기고 필요할 때 펼침
7. 예외만 표시: 미확인·의견만 배지
8. 휴대폰 하단 탭 5개(리포트·공고·커리어·지원·관리), PC는 왼쪽 메뉴. 상세 화면에는 하단 탭을 두지 않는다

## 디자인 스타일

F 미니멀 피드 배치에 E 블루 강조를 얹은 혼합안이다(캔버스 '혼합안 색 비교'의 블루). 색과 크기 값은 `web/src/styles/tokens.css` 한 곳에 두고, 화면 코드는 값을 직접 쓰지 않는다.

1. 바탕은 흰색이고 목록은 카드 없이 얇은 줄로 나눈다. 섹션 사이도 1px 줄이고, 심층분석처럼 성격이 바뀌는 곳에만 8px 회색 띠를 둔다.
2. 강조색(블루)은 정해진 곳에만 쓴다: 화면의 1등(오늘의 1등 카드), 점수, 고른 필터 칩, 하단 탭·왼쪽 메뉴의 현재 위치, 그래프의 강조 막대, ★, 글자 버튼(N건 더 보기, 다시 조사).
3. 점수: 목록은 연한 블루 상자에 블루 숫자, 화면의 1등만 블루 상자에 흰 숫자.
4. 빨강은 마감이 3일 이내(D-day~D-3)인 공고와 마감 임박 건수에만 쓴다.
5. 모서리: 카드 16, 점수 상자 12, 칩은 끝까지 둥글게. 숫자 칸과 표는 각지게.
6. 글꼴은 Noto Sans KR 하나(400·600·700), 숫자가 줄 맞춰야 하는 곳은 고정폭 숫자.
7. 어두운 화면은 아직 만들지 않는다(값은 tokens.css에만 있으니 나중에 한 곳에서 추가한다).
