# 내용과 화면 원칙

화면, 리서치, 매칭, 보고에 무엇을 어떤 형식으로 담나. 용어와 표기는 [용어집](glossary.md)을 따른다.

## 내용 원칙

1. 회사 리서치는 사실만 담는다. 해석과 제안(매칭 설명, 커리어 제안)에는 "AI 의견"을 붙이고 근거 링크를 단다.
2. AI가 쓴 문장마다 출처 URL이 있어야 하고, 없으면 버린다. 저장 전에 출처를 다시 열어 내용을 대조한다.
3. 숫자(실적, 임직원, 공시)는 공식 데이터를 그대로 쓴다. AI가 숫자를 만들지 않는다.
4. 사실 표시: 확인·보도는 배지 없음, 의견·미확인만 배지. 출처끼리 값이 다르면 둘 다 보여주고 미확인. 찾아봤지만 없으면 "찾지 못함".
5. AI 결과에는 설정 버전, 모델, 지시문 버전을 함께 저장한다.
6. 설정을 바꾸면 비용이 안 드는 필터는 전체에 바로 적용하고, AI 비용이 드는 것은 앞으로만 적용한다(원하면 골라서 재처리).

## 콘텐츠 형식 원칙

그릇은 고정하고 내용은 열어둔다. 형식을 너무 조이면 정보를 놓치고, 너무 풀면 화면과 문장이 매번 달라진다.

| 층 | 무엇 | 강도 |
| --- | --- | --- |
| 그릇 | 화면 블록 모양 | 항상 고정 |
| 칸 | 담을 항목 | 영역마다 다름(아래 표) |
| 문장 | 실제 글 | 길이와 규칙만 고정 |

- **블록 7개**: 숫자 카드·그래프, 라벨-값 줄, 비교 표, 사실 목록(날짜 + 한 줄 + 출처 + 배지), 단계 흐름, 인용, 칩. 화면의 모든 정보는 이 중 하나로 그린다.
- **AI 결과는 블록 형식의 JSON으로만** 받는다. 코드가 검증(필수 칸, 출처, 길이, 날짜 형식)하고, 실패하면 화면에 내보내지 않고 다시 생성하거나 버린다.
- **필수 칸과 찾아볼 주제를 나눈다.** 필수 칸은 데이터가 늘 있는 곳에만 둔다. 나머지는 주제로만 알려주고 못 찾으면 "찾지 못함". 주제 밖이어도 중요한 사실은 "기타"로 1~2개 허용한다.
- **고정 기준은 버전으로 관리한다**: 직무 분류, 스킬 사전, 매칭 점수 계산법, 수요 계산법. 바꾸면 버전을 올리고 지난 데이터를 다시 계산한다.
- **기준 샘플**: 공고 5개와 회사 5곳을 고정해 두고, 지시문이나 형식을 바꿀 때마다 다시 돌려 전후를 비교한다.
- **칸 올리기·내리기**: 자유 형식에 같은 정보가 자주 나오면 고정 칸으로 올리고, 고정 칸이 자주 비면 찾아볼 주제로 내린다.

| 영역 | 강도 | 고정 | 열어둠 |
| --- | --- | --- | --- |
| 공고 데이터 | 고정 | 필드, 값 형식, 직무 분류 | 원문 JD 보관 |
| 매칭 점수 | 고정 | 평가 항목, 가중치, 계산법 | - |
| 매칭 설명 | 반고정 | 맞는 점/부족한 점/지원 전략 구조, 개수·길이 상한, 근거 링크 | 문장 |
| 리서치 공시 숫자 | 고정 | 지표, 3년, 단위 | - |
| 리서치 서술 모듈 | 반고정 | 사실 목록 블록, 찾아볼 주제, 개수 상한 | 담을 사실, 기타 1~2개 |
| 커리어 지표 | 고정 | 직무 분류, 스킬 사전, 수요 계산법 | - |
| 커리어 해석·제안 | 반고정 | AI 의견 표시, 근거, 카드 구조 | 문장 |
| 아침 알림·오늘의 리포트 | 고정 | 항목 순서·개수, 문구 틀 | 항목 안 짧은 요약 |
| 프로필 | 반고정 | 경력·프로젝트·스킬 칸, 스킬은 사전 기준 | 프로젝트 설명 |
| 내 모듈 | 반고정 | 모듈 정의 형식, 결과는 사실 목록 | 조사 주제 |
| 화면 문구·표기 | 고정 | 용어집 | - |
| 디자인 | 고정 | 색·글자 규칙, 컴포넌트 | 화면별 배치 |

## 회사 리서치 모듈

기본정보(공고가 들어온 모든 회사, 공시·수집 데이터, 비용 거의 없음)와 심층분석(관심 회사·직접 요청, AI 웹 조사)으로 나눈다.

| 모듈 | 구분 | 형식 | 갱신 |
| --- | --- | --- | --- |
| 회사 개요 | 기본 | 정해진 칸(3년 실적 그래프, 주요 사업, 임직원·근속·연봉, 주요 공시) | 새 공시가 나오면 |
| 채용 | 기본 | 정해진 칸(열린 공고, 지난 1년 같은 직무 공고) | 매일 |
| 사업 구조 | 심층 | 자유(분야 + 한 줄, 주력·신사업) | 새 공시가 나오면 |
| 경쟁사 | 심층 | 표(같은 업종 매출 상위 2곳 자동) | 분기마다 |
| 직무 분야 전략 | 심층 | 사실 목록 | 관련 뉴스가 나오면 |
| 직무 조직 | 심층 | 사실 목록 + 찾지 못함 | 조직 개편 소식이 나오면 |
| 직무 환경·도구 | 심층 | 정해진 칸(클라우드, 플랫폼, BI, AI 도구) | 분기마다 |
| 업계 기초 | 심층 | 단계 흐름(밸류체인) + 사실 목록(최근 이슈), 업종끼리 공유 | 반기마다 |
| 현직자 리뷰 | 심층 | 인용, 의견 배지 | 매월 |

직무 분야 관련 모듈은 사용자가 고른 직무 분야(기본값 AI·데이터)로 조사한다. 내 모듈은 사용자가 문장으로 요청하면 AI가 정의를 만들고, 결과는 사실 목록 블록으로 보여준다.

## 화면 원칙

화면 구성은 [디자인 캔버스](https://claude.ai/artifact/5BJc5LRNaJCNgQRVuZ3PcE)의 '화면 구성' 페이지가 기준이다. 색과 모양은 아래 [디자인 스타일](#디자인-스타일)을 따른다.

1. 화면마다 가장 중요한 것 하나를 맨 위에 크게
2. 글자 크기(px): 페이지 제목 24, 섹션 17, 항목 제목 16, 본문 15, 보조 14, 최소 13
3. 굵기는 700(제목), 600(항목), 400(나머지)만
4. 설명 문장은 화면에 쓰지 않고 ? 아이콘이나 첫 사용 안내로
5. 목록 한 항목은 최대 4줄, 넘치면 말줄임
6. 출처·근거는 기본으로 숨기고 필요할 때 펼침
7. 예외만 표시: 미확인·의견만 배지
8. 휴대폰 하단 탭 5개(리포트·공고·커리어·지원·관리), PC는 왼쪽 메뉴. 상세 화면에는 하단 탭을 두지 않는다

## 디자인 스타일

F 미니멀 피드 배치에 E 블루 강조를 얹은 혼합안이다(캔버스 '혼합안 색 비교'의 블루). 색과 크기 값은 `web/src/styles/tokens.css` 한 곳에 두고, 화면 코드는 값을 직접 쓰지 않는다.

1. 바탕은 흰색이고 목록은 카드 없이 얇은 줄로 나눈다. 섹션 사이도 1px 줄이고, 심층분석처럼 성격이 바뀌는 곳에만 8px 회색 띠를 둔다.
2. 강조색(블루)은 정해진 곳에만 쓴다: 화면의 1등(오늘의 1등 카드), 점수, 고른 필터 칩, 하단 탭·왼쪽 메뉴의 현재 위치, 그래프의 강조 막대, ★, 글자 버튼(N건 더 보기, 다시 조사).
3. 점수: 목록은 연한 블루 상자에 블루 숫자, 화면의 1등만 블루 상자에 흰 숫자.
4. 빨강은 마감이 3일 이내(D-day~D-3)인 공고와 마감 임박 건수에만 쓴다.
5. 모서리: 카드 16, 점수 상자 12, 칩은 끝까지 둥글게. 숫자 칸과 표는 각지게.
6. 글꼴은 Noto Sans KR 하나(400·600·700), 숫자가 줄 맞춰야 하는 곳은 고정폭 숫자.
7. 어두운 화면은 아직 만들지 않는다(값은 tokens.css에만 있으니 나중에 한 곳에서 추가한다).
